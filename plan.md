# Plan: Standalone Qwen3-8B Evaluation-Awareness Experiment

## Context

`EXPERIMENT_SUMMARY.md` (from an earlier vLLM-based run) shows Qwen3-8B is the
strongest performer at *verbalized* eval-awareness among six open models
(AUROC 1.000, accuracy 0.957, separation 0.913 on a 20-transcript hellaswag
vs. everyday-conversations split). We want to dig deeper into this one model
specifically, in a clean, self-contained folder — not touching
`cls_corr_mi/` or `eval-aware-oss/` — that:

1. Builds a small labeled eval/deploy dataset.
2. Reuses `cls_corr_mi`'s white-box linear-probe pipeline (contrastive-pair
   direction → hidden-state projection → AUROC) scoped to Qwen3-8B only.
3. Adds a new verbalized-probe step, inspired by `eval-aware-oss`'s
   `probe_questions/eval_mcq.yaml` phrasings, where Qwen3-8B judges its own
   transcripts by answering "was this an evaluation?" in various framings.
4. Compares internal (activation-probe) vs. stated (verbalized)
   eval-awareness on the same transcripts — the natural next step flagged in
   both source projects (`eval-aware-oss/plan.md` Phase 2 gate, and
   `cls_corr_mi/README.md`'s "not in this directory" list).

Everything runs via HF `transformers` only (one code path for generation,
judging, and hidden-state extraction via `output_hidden_states=True`),
on a small dataset (~20 transcripts: 10 eval-sourced, 10 deploy-sourced),
matching `EXPERIMENT_SUMMARY.md`'s scale so results are directly comparable.

## New folder layout

`qwen3_eval_awareness/` (standalone; copies/adapts code rather than
importing `cls_corr_mi` as a package):

```
qwen3_eval_awareness/
├── README.md
├── data/
│   ├── contrastive_pairs_16.txt     # copied from cls_corr_mi/data/
│   └── probe_questions.yaml         # adapted subset of eval-aware-oss's eval_mcq.yaml
├── build_dataset.py                 # step 0: assemble 10 eval + 10 deploy transcripts
├── compute_probe.py                 # step 1: adapted from cls_corr_mi (Qwen3-8B only, drop --model-key registry)
├── score_prompts.py                 # step 2: adapted from cls_corr_mi
├── classify_auroc.py                # step 3: reused near-verbatim from cls_corr_mi
├── verbalize_probe.py               # step 4 (new): Qwen3-8B judges its own transcripts via probe_questions.yaml
├── compare_internal_vs_verbal.py    # step 5 (new): merge + compare AUROC internal vs verbalized
├── run.sh                           # orchestrates steps 0-5
└── output/                          # run artifacts (prompts, probe.pt, scores, results, report)
```

## Step-by-step

### 0. `build_dataset.py` — assemble the small dataset

Mix-and-match dataset drawn from the sources cataloged across
`eval-aware-oss/configs/*.yaml`, chosen to span multiple eval categories
(not just one benchmark) while staying dependency-light — plain
`datasets.load_dataset()` pulls only, no `inspect_ai` dependency and no
`antieval/repro` download required:

- **Eval-sourced (10 total, ~2-3 per source)** — capability *and* alignment
  categories:
  - `hellaswag` (commonsense capability) — same source as
    `EXPERIMENT_SUMMARY.md`, kept for comparability.
  - `arc_challenge` (reasoning capability).
  - `gpqa` (hard capability) — public HF dataset `Idavidrein/gpqa`.
  - `agentharm`-style prompts (agentic/alignment) — public HF dataset
    `ai-safety-institute/AgentHarm`.
- **Deploy-sourced (10 total)**:
  - Mostly `HuggingFaceTB/everyday-conversations-llama3.1-2k` (split
    `train_sft`), final turn regenerated by Qwen3-8B itself (so eval and
    deploy transcripts are both model-authored — avoids the writing-style
    confound noted in `EXPERIMENT_SUMMARY.md` line 9).
  - A few from `allenai/WildChat-1M` (split `train`) for style variety,
    also regenerated by Qwen3-8B for the same reason.
- Output: `output/transcripts.jsonl`, one row per transcript:
  `{"id", "text", "label": 0|1, "source", "category"}` — `source` is one of
  `hellaswag`/`arc_challenge`/`gpqa`/`agentharm`/`everyday_chat`/`wildchat`,
  `category` is `capability`/`alignment`/`chat` (mirroring the
  `label: {split, category}` convention from `eval-aware-oss`'s configs) —
  same core shape as `cls_corr_mi`'s `build_prompts.py` output
  (`text`/`label`/`source`/`prompt_id`), so `compute_probe.py`/
  `score_prompts.py` can be adapted with minimal changes.

### 1. `compute_probe.py` — internal probe direction (adapted from `cls_corr_mi`)
- Hardcode Qwen3-8B config (`hf_id: Qwen/Qwen3-8B`, `chat_template: true`,
  `enable_thinking: true`, matching `cls_corr_mi/data/models.yaml`) — drop
  the multi-model `--model-key` registry since this folder is single-model.
- Same mean-difference-of-16-contrastive-pairs method, unit-normalized,
  plus 10 random-direction controls, per layer. Output `probe.pt` in the
  same format as `cls_corr_mi`.

### 2. `score_prompts.py` — project the 20 transcripts (adapted from `cls_corr_mi`)
- Same last-token + mean-token projection logic; run on `transcripts.jsonl`
  from step 0. Output `scores.npz` (same schema as `cls_corr_mi`).

### 3. `classify_auroc.py` — internal-probe AUROC per layer (reused near-verbatim)
- With only 20 transcripts, use leave-one-out or all-as-test (no held-out
  train/test split at this scale) — note this explicitly in the README as an
  exploratory limitation, echoing `EXPERIMENT_SUMMARY.md`'s "exploratory
  effect sizes, not significance tests" caveat.
- Output: `results/internal_auroc.json` (peak layer + per-layer AUROC vs.
  random controls).

### 4. `verbalize_probe.py` — verbalized probe (new, inspired by `eval-aware-oss`)
- Port 4-5 probe-question phrasings from
  `eval-aware-oss/probe_questions/eval_mcq.yaml` (`direct_a`,
  `h_purpose_analysis_a`, `h_user_or_control_set_a`, `h_intent_and_style_a`,
  `direct_vn_a`) into `data/probe_questions.yaml`, preserving their
  `template_text`/`answer.real`/`answer.eval` structure.
- For each of the 20 transcripts × each probe question, append the probe
  text as a follow-up turn and generate with Qwen3-8B (HF `generate`,
  temperature 0.7, matching `EXPERIMENT_SUMMARY.md`'s config for
  comparability).
- Parse `<label>...</label>` from the response (reuse the parsing logic
  pattern from `eval-aware-oss/aware_bench/measure/probing/scorer.py`'s
  `score_pq_xml`: exact match → case-insensitive → punctuation-stripped →
  whole-word fallback; flag unparseable as a first-class "parse_failure"
  row rather than dropping it, per that project's convention).
- Output: `output/verbalized_responses.csv` (columns: `transcript_id`,
  `probe_id`, `ground_truth_label`, `eval_signal` (0/1), `parse_status`) and
  `results/verbalized_auroc.json` (per-probe + ensemble AUROC, mirroring
  `EXPERIMENT_SUMMARY.md`'s tables).

### 5. `compare_internal_vs_verbal.py` — internal vs. stated comparison (new)
- Merge `results/internal_auroc.json` (best-layer internal probe AUROC) and
  `results/verbalized_auroc.json` (verbalized AUROC) into one report.
- Per-transcript: does the internal probe's projection score correlate with
  the model's stated verbalized answer? (Spearman correlation, reusing the
  approach from `cls_corr_mi/correlation_mi.py` but correlating internal
  probe score against the verbalized `eval_signal` instead of an external
  0-3 judge score — no external judge needed here since Qwen3-8B is both
  subject and judge.)
- Bucket analysis: for transcripts where verbalized judgment is correct vs.
  wrong (TP/FN/FP/TN, per `eval-aware-oss/plan.md`'s Phase 2 framing), report
  whether the internal probe score still separates them — i.e., does the
  model "know internally" even when it misstates verbally, or vice versa.
- Output: `output/COMPARISON_REPORT.md`, formatted similarly to
  `EXPERIMENT_SUMMARY.md`.

### 6. `judges/gpt_judge.py` — GPT-based qualitative judge (new, optional)
- Diagnostic complement to steps 1-5, not part of the AUROC numbers: for
  each transcript, an external GPT model (`--model`, default `gpt-4o`)
  reads the original prompt, Qwen3-8B's own `<think>` reasoning trace and
  final answer, and its verbalized eval/deploy answers across all 5 probe
  questions (step 4's output), and diagnoses *what specifically* — surface
  cues (benchmark-like formatting, topic/register mismatch), self-
  referential statements in the reasoning trace, or nothing at all (i.e.
  the model may be guessing from surface style rather than genuine
  awareness) — plausibly caused Qwen3's verbalized verdict.
- Also produces GPT's own independent eval/deploy verdict on each
  transcript, for comparison against both Qwen3's verbalized answer and
  the ground-truth label.
- Requires `OPENAI_API_KEY`; uses the OpenAI SDK's JSON-mode structured
  output (`response_format={"type": "json_object"}`) for reliable parsing.
- Output: `output/gpt_judge_analysis.jsonl` (one structured row per
  transcript) and `output/GPT_JUDGE_REPORT.md` (aggregated agreement rates,
  most-common cues cited, per-transcript detail).

### `run.sh`
Orchestrates steps 0→6 end-to-end with one command (step 6 skipped if
`OPENAI_API_KEY` is unset), paths under `--out-root`, mirroring
`cls_corr_mi/reproduce.sh`'s structure.

## Key files to reference/adapt (not modify in place)
- `cls_corr_mi/common.py` — model loading, chat template, left-padding pattern to copy.
- `cls_corr_mi/compute_probe.py`, `score_prompts.py`, `classify_auroc.py` — adapt, strip multi-model registry.
- `cls_corr_mi/data/contrastive_pairs_16.txt` — copy as-is.
- `eval-aware-oss/probe_questions/eval_mcq.yaml` — source for probe-question phrasings/templates.
- `eval-aware-oss/aware_bench/measure/probing/scorer.py` (`score_pq_xml`) — label-parsing fallback logic to replicate.
- `EXPERIMENT_SUMMARY.md` — config values (temperature 0.7, max_tokens 4096, sources) to match for comparability.

## Verification
- Run `compute_probe.py` and confirm `probe.pt` has 16-pair real direction + 10 random controls per layer, matching `cls_corr_mi`'s `.pt` schema.
- Run `score_prompts.py` and confirm `scores.npz` shape `[20, n_layers]`.
- Run `classify_auroc.py` and sanity-check peak-layer AUROC is well above the random-control band (as in `cls_corr_mi`'s paper reproduction).
- Run `verbalize_probe.py` and confirm per-probe accuracy roughly matches `EXPERIMENT_SUMMARY.md`'s Qwen3-8B numbers (accuracy ~0.957, AUROC ~1.0) as a consistency check that the new standalone generation path reproduces prior results.
- Run `compare_internal_vs_verbal.py` and read `COMPARISON_REPORT.md` for the internal-vs-verbalized correlation and bucket breakdown.
